Features

Everything you need at the table

Focused on the in-session experience — a map, tokens, fog, and dice — not a rules engine to wrestle with.

🗺

Maps & fog of war

Upload any map image, drop a grid on it, and reveal the dungeon as the party explores. Players only ever see what you've uncovered — the rest stays dark.

🎭

Tokens with custom art

Give every creature, NPC, and player a token image. Drag them around the map and everyone sees the move live. Drop an ambush in as a hidden token and reveal it when it strikes.

🔒

Public & hidden stats

Each creature can carry a public stat block and image players see on click — plus a DM-only block and image only you ever see. The hidden parts never leave your server.

🔗

Share-link player view

Send players one link — no account, no install. They see the fog-covered map, live tokens, click a token for its public info, and switch to the handout you're showing.

🎲

Dice for everyone

A shared roll log the whole table watches. Roll 2d20+5 in the open, or roll silently behind the screen — players can roll in secret too.

🖼

Gallery & handouts

Keep character art, maps, and item cards in a campaign gallery, then push any of them to your players' screens the moment the reveal lands.

📓

Notes, public or secret

Rich-text notes for lore, plot, and recaps — keep them DM-only, or publish one to the party as a handout when the prophecy is read aloud.

👥

Multi-DM & live presence

One server hosts many DMs, each with their own secured campaigns. See who's at the table in real time; everything syncs instantly over WebSocket.

How it works

From empty server to live game night

Set the scene on your side, then hand your players a link.

1

Create your DM account

Register on your server and make a campaign. Your maps, creatures, and secret notes are private to you.

2

Build the scene

Upload a map, add creatures to your library with token art and stats, and drop them onto the board.

3

Run the session

Reveal fog as they explore, move tokens, push a handout, and roll dice — openly or in secret.

4

Share the link

Send players the share link. They join instantly — no account — and see only what you've revealed.

Under the hood

Built to run on your own box

A clean, self-contained stack that comes up with one command — and keeps the hidden stuff hidden on the server, not just in the UI.

StackFastAPI (Python) · PostgreSQL · Next.js (TypeScript)
RealtimeNative WebSockets — token moves, fog, handouts, dice, presence, with per-connection permission filtering
SecurityHidden creature stats, hidden images, hidden tokens and private rolls are enforced in the API — a player client is never sent them
PlayersLink-only via a revocable share token · no account needed · optional password & expiry
StorageMap / token / gallery images on a local volume · DM-only images served only to the owning DM
DeployDocker Compose · PostgreSQL + Alembic migrations · runs on a home server or a cheap VPS · no telemetry, no cloud

GameTable focuses on the shared table — maps, tokens, fog, and dice. It deliberately leaves automated rules, lighting, and voice to your other tools.

Self-host

Up and running in minutes

Docker and a machine to run it on — that's all. One command brings up the database, API, and web app.

# Clone, configure, and launch
git clone https://github.com/mnavas/gametable.git
cd gametable
cp .env.example .env            # then set JWT_SECRET to a long random string
docker compose up --build

# Then open the web app and register the first DM account
#   web  → http://localhost:3000   (the first account becomes the server admin)
#   api  → http://localhost:8001/docs

Full setup, ports, environment variables, and production notes are in the installation guide. New to running a game here? See the DM guide and the player guide.
